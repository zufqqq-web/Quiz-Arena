Контекст: QuizCraft — React + TypeScript фронт (live-квиз конструктор, kahoot-like) + Node/Express/
Socket.IO бэкенд на /server. Мультиплеер уже полностью рабочий (WebSocket-синхронизация между
устройствами протестирована и подтверждена). AI-генерация квизов частично реализована
(POST /api/generate-quiz на сервере, aiService.ts на фронте с fallback на CURATED_TEMPLATE_PACKS).

=== ЗАДАЧА №1: Диагностика и фикс AI-генерации квизов ===

Проблема: при вводе темы (например "JavaScript квиз") и настроенного провайдера/токена/модели
через AISettingsModal — результат всегда выглядит как нерелевантный шаблон "ни о чём"
(про колёса машины, бананы, Лувр и т.п.), а не реальные вопросы по заданной теме.

Скорее всего причина: src/services/aiService.ts тихо ловит ошибку (сеть/сервер/провайдер)
и откатывается на CURATED_TEMPLATE_PACKS (см. catch-блок и console.warn в generateQuizWithAI),
а пользователь не видит текст реальной ошибки, потому что она уходит только в консоль браузера.

Нужно сделать:
1. Проверь весь путь запроса end-to-end:
   - Открой консоль браузера при генерации квиза, найди console.warn с текстом ошибки
     ('[QuizCraft AI] Remote AI generation returned ...' или 'Server unreachable ...').
   - Проверь server/src/aiProvider.ts: правильно ли обрабатывается ответ от указанного
     провайдера (Gemini / OpenAI-совместимый), не падает ли парсинг JSON, не обрезается ли
     ответ модели.
   - Проверь, действительно ли aiConfig (baseUrl, apiKey, model) из AISettingsModal доходит
     до сервера в теле запроса POST /api/generate-quiz — залогируй на сервере входящий aiConfig
     (без самого apiKey в лог, только baseUrl и model) перед вызовом generateQuizQuestions().
2. Замени тихий fallback на ВИДИМЫЙ для пользователя:
   - В aiService.ts: если запрос к /api/generate-quiz упал (response.ok === false ИЛИ
     произошла сетевая ошибка) — верни отдельно флаг/причину наружу (например через callback
     onFallback(reason: string) или через возвращаемый объект { questions, usedFallback: boolean,
     errorReason?: string }), чтобы UI мог показать пользователю тост/уведомление
     "Не удалось сгенерировать через ИИ (причина: ...), использован демо-шаблон" —
     вместо молчаливой подмены на шаблон без объяснений.
   - Компонент, вызывающий generateQuizWithAI (AITemplateModal.tsx / AIChatWidget.tsx),
     должен показывать эту причину пользователю явно (toast/inline-сообщение), а не просто
     тихо подставлять готовые вопросы.
3. Проверь и укрепи normalizeQuestions() в server/src/aiProvider.ts — если модель вернула
   валидный JSON, но с чуть другими именами полей/структурой (например vari

ации в написании
   ключей) — сделай парсинг более терпимым (trim полей, fallback на разумные дефолты),
   чтобы не ронять весь ответ из-за мелких отклонений формата.
4. Добавь в SYSTEM_PROMPT в aiProvider.ts более явное требование учитывать topic дословно:
   "The generated questions MUST be directly and specifically about the exact topic provided
   by the user. Do NOT generate generic trivia questions unrelated to the topic." — некоторые
   модели могут игнорировать topic при низком temperature/маленьком промпте, усиление
   инструкции снижает этот риск.
5. Добавь в language (сервер + типы, GenerateQuizParams в aiService.ts и GenerateQuizRequest
   в server/src/types.ts) поддержку 'uz' (узбекский) как третьего варианта наравне с 'ru'/'en' —
   в SYSTEM_PROMPT добавь ветку "Language: Uzbek" аналогично текущей ru/en логике.

=== ЗАДАЧА №2: Смена языка интерфейса (RU / EN / UZ) ===

Сейчас весь текст интерфейса (кнопки, заголовки, подписи, сообщения) захардкожен на русском
прямо в JSX по всем компонентам. Нужно добавить переключатель языка интерфейса на 3 языка.
Язык — per-browser настройка (каждый пользователь выбирает свой язык независимо,
не синхронизируется через сервер/комнату).

Нужно сделать:
1. Создай src/i18n/translations.ts (или папку src/i18n/{ru,en,uz}.ts) со структурой:
   объект с плоскими или вложенными ключами для каждого языка, покрывающий весь
   пользовательский текст интерфейса: кнопки, заголовки экранов, подписи полей,
   сообщения об ошибках, тексты в модалках (включая AISettingsModal), названия статусов
   игры и т.д. Пройдись по всем компонентам в src/components/**/*.tsx и вынеси
   ВЕСЬ хардкоженный русский текст в JSX (кроме пользовательских данных типа названий
   квизов/вопросов, которые не переводятся) в этот словарь.
2. Создай src/utils/i18n.ts с:
   - getLanguage() / setLanguage(lang: 'ru'|'en'|'uz') — чтение/запись в localStorage
     (ключ 'quizcraft_language'), дефолт 'ru'.
   - Простой React Context (LanguageProvider) в src/contexts/LanguageContext.tsx,
     оборачивающий App.tsx, предоставляющий текущий язык и функцию t(key: string) для
     получения перевода по ключу.
3. Замени весь захардкоженный текст в компонентах на вызовы t('some.key') через
   useLanguage()/useContext хук.
4. Добавь переключатель языка (простой dropdown/segmented control с флагами или
   аббревиатурами RU/EN/UZ) в шапку/навбар HomePage.tsx и QuizLibrary.tsx (там, где
   уже есть кнопка настроек ИИ — рядом с ней логично разместить и переключатель языка).
5. НЕ переводи: содержимое пользовательских квизов (названия, вопросы, варианты ответов —
   это данные, а не UI), никнеймы игроков, названия квизов из библиотеки.

=== ЗАДАЧА №3: Кастомизация цветовой темы приложения ===

Сейчас цвета зашиты через Tailwind-классы напрямую (bg-amber-500, from-amber-300 и т.п.)
по всем компонентам. Нужна возможность выбрать акцентный цвет темы (как смена акцента
в дарк-моде), применяющийся глобально ко всему приложению.

Нужно сделать:
1. В src/index.css определи CSS-переменные для акцентного цвета в :root, например:
   --accent-h, --accent-s, --accent-l (HSL-компоненты) или набор
   --accent-50 .. --accent-900 (полная палитра оттенков одного акцентного цвета).
   Оставь текущую тёмную (slate) палитру фона/текста без изменений — меняется
   только акцентный цвет (сейчас в основном amber/orange).
2. Создай src/utils/theme.ts с:
   - Набор из 5-6 preset-тем (например: Amber/Orange — текущий дефолт, Blue, Purple,
     Emerald, Rose, Cyan) — каждая задаёт значения CSS-переменных.
   - getTheme() / setTheme(themeName: string) — чтение/запись в localStorage
     (ключ 'quizcraft_theme'), применение через document.documentElement.style.setProperty().
3. Пройдись по компонентам и замени хардкоженные Tailwind-классы акцентного цвета
   (bg-amber-500, text-amber-300, from-amber-300, border-amber-500 и все их вариации/
   оттенки/прозрачности, использующиеся как ГЛАВНЫЙ акцентный цвет бренда — не путай
   с семантическими цветами типа красный=неправильный ответ, зелёный=правильный ответ,
   которые должны остаться как есть) на использование CSS-переменных через inline style
   или через Tailwind arbitrary values типа bg-[var(--accent-500)].
   Приоритет — заменить в самых заметных местах: HomePage.tsx (кнопки, градиенты,
   логотип), QuizLibrary.tsx, HostLobby.tsx, PlayerJoin.tsx, кнопки в модалках.
   Не обязательно менять каждый пиксель — фокус на кнопках, акцентных градиентах,
   активных состояниях, а не на второстепенных декоративных элементах.
4. Добавь UI для выбора темы: простую панель/dropdown с кружками-превью цветов
   (5-6 preset), размести рядом с переключателем языка и кнопкой настроек ИИ в шапке.
